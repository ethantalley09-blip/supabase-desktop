## What was built

### 1. Governing mode (migration `0042_governing_mode.sql`)
A campaign that wins switches the **same project** into an officeholder workspace. The data carries over, so the customer keeps paying through the term and switches back to campaign mode for re-election. This is the main fix for election-day churn identified in the growth research.

- **Switch:** the header button "We won — switch to Governing" (`src/features/projects/ModeSwitch.jsx`) sets `projects.mode`, `office_title` and `term_ends_on`. "Start re-election campaign" switches back.
- **Office tab** (`src/features/governing/`) is visible only in governing mode:
  - a case log for constituent requests (`constituent_cases`)
  - a work queue sorted overdue first, then priority, then oldest
  - an append-only timeline per case (`case_updates`), with status changes logged automatically by trigger
  - stats: open, overdue, median days to resolve, new in the last 30 days
  - a nudge to switch back when re-election is under 18 months away
- **AI:**
  - `constituent_reply` drafts a reply. It sends the first name only, never contact details, and the prompt forbids any campaign ask.
  - `office_briefing` writes a chief-of-staff summary from totals only.
- **Permissions:** `governing.view` / `governing.manage` go to Owner, Manager and Media across all 4 org types.
- Pure logic: `governingMath.js` (13 tests).

### 2. Workspace (migration `0043_workspace.sql`): ease of use and navigation
The app has 80+ tools across about 10 tabs. These six features help users find things and know what to do next.

| Feature | Where | How it works |
|---|---|---|
| **Search & Jump** | Ctrl/⌘+K, or the **Search** button in the header | `CommandPalette.jsx`. Finds any tab, action or AI tool the viewer can open. Arrow keys and Enter to navigate. |
| **Ask Lynx** | **Ask Lynx** button in the header | `AskLynx.jsx`, AI purpose `app_guide`. Plain-English how-to with buttons that open the right tool. Without AI it falls back to keyword suggestions. |
| **Today** | Top of Overview | Up to 6 real "do this next" items, each with a **Go** button. **+** turns an item into a task. |
| **Launch Checklist** | Top of Overview (managers) | 5–7 setup steps detected from real data, never ticked by hand. Can be hidden once done. |
| **Team Tasks** | New **Tasks** tab, plus "My tasks" on Overview | `team_tasks` table. One-line quick add, assignee, due date, overdue shown in red, links back to where the work happens. |
| **Weekly Recap** | Overview (managers) | AI purpose `weekly_recap`. This week vs. the same point last week; saved in `weekly_recaps` so you can page back through past weeks. |

**Design rules to keep:**
- `buildNavIndex` (`navMath.js`) is the single list of places a viewer can go. When you add a tab or action to the app, add it there too.
- Ask Lynx sends the model **only** that list, and `resolveGuideIds` drops any id the model invents. It can never offer a button to something the user can't open.
- `weekly_recaps` is limited to managers (`projects.manage`) because it stores money raised, which Canvassers can't see anywhere else.
- Overview loads eagerly, so keep Workspace imports light. That's why `useOrgMembers` lives in `useWorkspace.js` rather than being imported from `useFundraisingAi.js`. Workspace adds about 7 KB gzipped to the first page load.
- Pure logic lives in `navMath.js` and `workspaceMath.js` (21 tests).

Other small improvements made along the way:
- The tab bar wraps instead of overflowing.
- Deep links retry the scroll for up to about 2 seconds, so links into lazily loaded tabs don't miss.
- `openTool` now also blocks links to the Compliance and AI tabs when they're hidden.

### 3. Workspace round 2 (migration `0044_notifications.sql`)
- **Notifications bell** in the project header, with an unread badge. You're notified when someone assigns you a task or a constituent case, or finishes a task you created. Clicking a notification opens the right tab, or the right project if it belongs to another one. "Mark all read" is included. It refreshes every minute and when you return to the window.
- **Safety:** only database triggers can create notifications. Users can only mark their own as read; they can't edit the text. You're never notified about your own actions, and case notifications show only the subject, never the private details.
- **New guards:** tasks can only be assigned to active org members, and constituent cases only to people whose role can open the Office tab.
- **Pinned & recent** in Search & Jump: star any result to pin it to the top. Pins follow you between devices. Places you've recently opened appear before you type.
- **"Start here" guides:** a short strip at the top of every tab explaining what it's for, with buttons for its key actions. Hiding it leaves a one-line "About this tab" link so it can be reopened.
